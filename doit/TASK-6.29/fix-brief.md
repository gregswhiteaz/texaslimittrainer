## 1. [MAJOR] tools/lint/headless-boundary.js:node-process-global-open (security review)
- Where: tools/lint/headless-boundary.js:143
- Problem: The Node `process` global is still open in bot and advice code. It is just as simple as the `global` alias this task closes, and arguably a bigger hole. `process.hrtime()`, `process.hrtime.bigint()` and `process.uptime()` give non-seeded randomness (REQ-028.1). `process.getBuiltinModule('node:crypto')` (available on the repo's Node v22.18) loads a Node module at runtime, which no-restricted-imports and the bot/advice import allow-lists cannot see. `globalThis.process.hrtime()` also passes. D-2's reasoning (no legitimate use in browser-targeted bot code) applies equally to `process`. `process` is a Node global rather than a browser-only one, so BROWSER_ONLY_GLOBALS / no-restricted-globals does not cover it. tsconfig.json includes `types: ["node"]` for src, so these calls also pass typecheck.
- Evidence: Contributed bot code (the threat model in spec 8) writes `export const r = process.hrtime()[1];` or `process.getBuiltinModule('node:crypto').randomInt(10)` in src/bots/x.ts, src/advice/x.ts or src/engine/bot-random.ts. In-process ESLint with the repo config (lintText, same as the new test) reports 0 errors for each of these: process.hrtime(), process.hrtime.bigint(), process.uptime(), globalThis.process.hrtime(), process.getBuiltinModule(...). In Node (playtest and tests), bot decisions then depend on the clock or the OS CSPRNG instead of the seeded generator. That breaks REQ-028.1 reproducibility, and getBuiltinModule gets around the REQ-025.1 import boundary. grep finds no `process` in non-UI src/, so a ban causes no false positives.
- Expected fix: In FUNCTION_AND_GLOBAL_ESCAPES, extend the B6 selector to `Identifier[name=/^(global|process)$/]` + NAME_ONLY_POSITIONS (or add a separate `process` entry with its own probe so it stays load-bearing). Also add `{ object: 'globalThis', property: 'process' }` to botDeterminismConfig no-restricted-properties. Add probes `process.hrtime()` and `globalThis.process` to the new test. If the team decides this is outside the AC, record it as a follow-up task rather than dropping it.
