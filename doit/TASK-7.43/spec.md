# Spec: TASK-7.43 — Resize the authored opponent range and rank hands by three-way equity when scaling observed opponents

Status: READY (approved 2026-11-26, autopilot)

## 1. Summary
Once an opponent has been watched for 30 hands, `estimateOpponentRanges` stops using the authored default range.
It uses the strongest `width` % of a hand order instead. That order ranks hands by equity against one random
hand, so K2o, Q2o and J2o rank above 87s, 76s and 65s. This story carries out decision-5 (TASK-7.29 Q-1 B and
Q-2 B). The observed range becomes the authored default resized to the scaled width (TASK-7.29 rule A-5).
`hand-order.json` is regenerated by seeded `computeEquity` against three random hands. The story also re-pins
the locked expectations this changes and updates the docs.

### Components, interfaces and data
```ts
/** The authored default `classes` resized to `widthPct` % of 1326 combos by HAND_ORDER (TASK-7.29 A-5). */
export function resizeRange(classes: ReadonlySet<HandClass>, widthPct: number): ReadonlySet<HandClass>;
```
- Pure, with no errors thrown. It is never called with an empty set (§3). For robustness, an empty `classes`
  takes the widening branch and so returns the `HAND_ORDER` prefix.
- `hand-order.json` keeps the shape `{format: "tlh-hand-order", version: 1, justification, hands: [[class, pct], …]}`.

### Rules and algorithms
1. **Resize (A-5).** `target = widthPct / 100 × 1326 − 1e-9`, and `total` = the combos of `classes`.
   - **Narrow or keep** (`total ≥ target`): walk `HAND_ORDER` and skip classes not in `classes`. Add each one
     until the set is non-empty and its combos are ≥ `target`. The result is the shortest strongest-first run of
     the default and always holds the default's strongest class.
   - **Widen** (`total < target`): start from all of `classes`. Walk `HAND_ORDER`, skipping members, and add
     each class until the combos are ≥ `target`. `widthPct ≥ 100` gives all 169 classes.
   - Worked examples, 6-max:
     - BB `call-raise` d = 41.48. At width 41.48 the result is the default exactly: it keeps 22 and 54s-98s and
       has no AA.
     - At 60 it adds the strongest missing classes (AA, KK, …) until the combos reach 795.6.
     - UTG `open-raise` at width 0 gives {AA}.
     - CO `call-raise` at width 0 gives {its strongest default class in the new order}, not AA.
2. **Estimator.** The rest of `estimateOpponentRanges` is unchanged: basis, dead cards, the empty-start
   fallback and narrowing.
3. **Order generation (A-4).** Run it once and commit the output. Today's file was computed by the same
   procedure against one opponent. Measured results: AA 63.9 is first and 32o 14.1 is last. 87s is #68 (26.8),
   76s #81 (25.2), 65s #93 (23.9), K2o #112 (22.0), Q2o #131 (20.5), J2o #144 (18.9). `parseHandOrder` must
   accept the result.
4. **Docs (`range-model.md`).**
   - "Hand order" must state the resize rule (rule 1), including that an observed opponent at the default width
     keeps the authored range. It must also state the floor and the all-169 cap, and the three-random-hands
     procedure (A-4, 30,000 sampled deals seeded from the input, one decimal place, grid-order ties). It ends
     with "AA (63.9%) is first and 32o (14.1%) is last".
   - "Known limits":
     - Delete the sentence starting "Equity against one random hand values offsuit high-card hands…".
     - Keep the re-raise sentence and change its pointer to "A follow-up task (TASK-7.44) scales them relative
       to a typical PFR".
     - Add the A-7 small-pairs sentence.
   - Neither paragraph may mention "strongest `width` %" or "one random hand" as current behaviour.

### hand-order.json justification (exact)
`This order ranks all 169 starting-hand classes from strongest to weakest by one objective measure: the share of the pot each hand wins when it is all in before the flop against three opponents, each holding any random two cards. Each number was computed with this project's own equity calculator, using the class's lowest-numbered combo and every unseen combo as each opponent's range, with 30,000 sampled deals seeded from the input, then rounded to one decimal place. Hands with equal rounded numbers keep the starting-hand grid order. Against three hands, suited connectors such as 76s rank above offsuit hands with one high card such as Q2o, which is closer to how they play at a real table. The order is used only when an observed opponent's preflop range is resized to match how often that player raises or calls: a wider range adds the strongest hands from this list that the typical-player range lacks, and a narrower range keeps the strongest of the typical-player hands, always at least one.`
