## 1. [MAJOR] tests/ci/retry.sudo.test.ts:spec02-does-not-prove-sudo-fallback-ran (code review)
- Where: tests/ci/retry.sudo.test.ts:211
- Problem: The real-sudo acceptance test (SPEC-02) never checks that the EPERM -> `sudo -n kill` path actually ran. It only checks the outcome: two timeouts, a final error, and no leftovers. That outcome is also reached when sudo itself kills the whole command. So the test can pass on Ubuntu 24.04 without testing the fix at all, and it does not check the design's key assumption (the root orphan stays in the attempt's process group).
- Evidence: Builder's concern: sudo >= 1.9.14 with `Defaults use_pty` (Ubuntu 24.04 sudoers) runs the command under a root monitor in a new session/process group, and that monitor relays signals to the command's whole process group. In that mode, retry's SIGTERM reaches the sudo front end, the monitor sends SIGTERM to the group with sh+flock+sleep, and all of them die. Attempt 2 then gets the lock and every assertion at lines 211-216 passes. It would pass equally on the pre-change retry.js, so the spec's claim that it fails before the change is not guaranteed. In the same mode, a real apt-get that ignores or outlives SIGTERM sits outside pgid P: `sudo -n kill -- -P` misses it, `groupExists(P)` returns false (ESRCH), and reap reports success while the lock is still held. That is the run #68 failure again, and this test cannot show it. In non-pty mode the test does exercise the fallback. Which mode the runner uses is decided only by the environment, and nothing in the test records it.
- Expected fix: Add an assertion that the fallback was used, e.g. `expect(stdout).toMatch(/retry: could not send SIG(TERM|KILL) to process group \d+ \(EPERM\)/)` and `expect(stdout).toMatch(/retry: sent SIGKILL to process group \d+ with sudo/)`. If CI then fails because sudo runs under use_pty, the spec's assumption ('the orphan stays in the attempt's group', Not doing: /proc walk) is shown to be wrong and must go back to spec. Do not let it pass silently. Optional: on failure, log `ps -o pid,pgid,sid,ruid,args` for the marker so the CI log shows the group layout. The file is locked, so the orchestrator must allow this change.
